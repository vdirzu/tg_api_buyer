# Проверка реализации

Проверено в облачной среде на Python 3.12 и PostgreSQL 16:

- 45 автоматических тестов: реальная PostgreSQL, уникальная схема для каждого теста,
  применение настоящих Alembic-миграций перед тестом; все прошли.
- Полный сценарий Telegram через aiogram Dispatcher и тестовую HTTP-сессию:
  выбор RU, валюта, каталог, приём ключа, профиль и история, резерв вывода,
  админ-редактирование товара, фото, отклонение выплаты и dashboard.
- Одновременные попытки принять один ключ разными пользователями, разные ключи
  одним пользователем, повторные выплаты и превышение доступного баланса.
- Откат начисления и резерва при ошибке записи финансовой операции.
- Сбой курса, сохранение ожидающей проверки без plaintext, повтор после восстановления.
- Миграции upgrade → downgrade base → upgrade; alembic check без различий схемы.
- Ruff lint и форматирование; повторная установка uv sync --frozen.
- Docker-образ собран с TLS-проверкой и существующим доверенным CA через BuildKit secret.
- В Docker образе от непривилегированного пользователя с read-only root filesystem:
  CLI check успешно подключился к реальной PostgreSQL и прочитал 10 записей CSV.
- docker compose config --quiet и lookup синтетического ключа из sample CSV.

Не подтверждено в этой среде:

- Доставка и polling в настоящем Telegram: BOT_TOKEN не предоставлен. Запуск корректно
  прекращается с сообщением о необходимости токена до сетевого подключения.
- Живой курс USD/RUB: запрос заблокирован текущим сетевым прокси (ProxyError).
  Кеш, формат ответа, давность курса, ошибки HTTP и восстановление проверены через
  httpx MockTransport. В черновике среды добавлены api.telegram.org и open.er-api.com;
  сохранение черновика само по себе не применяет сетевую политику.
- Выполнение GitHub Actions на удалённом сервере проверяется после push; локальное
  выполнение тех же проверок не является подтверждением удалённого CI.

Для реального запуска нужны свой BOT_TOKEN, реальный ADMIN_IDS, постоянные секреты,
рабочий PostgreSQL и сетевой доступ. Никаких реальных банковских или криптовалютных
переводов во время проверки не выполнялось. CSV-проверка остаётся тестовой.

Исправление Windows/psycopg: добавлен общий запуск с SelectorEventLoop для Windows,
проверены возврат результата, обработка исключений и выбор SelectSelector. Миграции
и CLI check дополнительно проверены на реальном PostgreSQL через psycopg на Linux.
Для нативного Windows добавлена отдельная CI-задача; её удалённый результат здесь
не подтверждён.

Исправление кодировки Windows: явный UTF-8 для JSON-локалей, dotenv и генератора CSV.
Регрессионный тест имитирует CP1251 по умолчанию, проверяя чтение RU/EN локалей.
Дополнительно проверен UTF-8 путь CSV в .env. Отказ авторизации локального
PostgreSQL пользователя требует проверки учётных данных на компьютере владельца;
доступ к его PostgreSQL из облачной среды не выполнялся.
